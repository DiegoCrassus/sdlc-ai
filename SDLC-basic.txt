AI NATIVE SDLC MODEL
====================================================================

The SDLC must follow this lifecycle:

1. Ticket / Idea
   - Capture request, business intent, constraints and acceptance criteria.

2. Requirements
   - Refine scope, rules, assumptions, risks and non-goals.

3. Architecture
   - Define technical approach, boundaries, trade-offs and impacted areas.

4. Implementation
   - Implement through scoped tasks using deterministic rules.

5. Validation
   - Run tests, checks, QA notes and evidence collection.

6. PR & Review
   - Review diffs, risks, security, maintainability and regression impact.

7. Deployment
   - Prepare safe release, rollback notes and environment assumptions.

8. Observability
   - Define logs, metrics, traces, dashboards and expected signals.
   - Emit SDLC pipeline metrics via pre_task.py / post_task.py hooks.

9. Incident
   - Capture diagnosis, mitigation, communication and post-mortem.

10. Auto Fix
    - Suggest or prepare corrective changes using evidence from previous stages.

This lifecycle must be represented in YAML and documentation.

NEW SKILLS — DETAILED REQUIREMENTS
====================================================================

9. branch-naming.md
   Convention: <prefix>/SDLCINVEST-N-issue-gh-N-imperative-slug
   Prefixes: feature/ | bugfix/ | hotfix/ | docs/ | infra/ | refactor/ | sdlc/ | test/
   Rules: English slug, kebab-case, max 5 words, imperative verb.
   Lifecycle: created by IssueAnalyst → used in PR → deleted by DevOps on merge/close.

10. container-validation.md
    Gate: runs after every Dockerfile or docker-compose change.
    Procedure:
    - docker build --check (syntax only)
    - docker compose build --no-cache
    - docker compose up -d && wait 10s
    - docker compose ps: all services must be "healthy"
    - docker compose down -v
    Exit 0 only if all services healthy.

11. e2e-testing.md
    Gate: mandatory for every PR touching app/frontend/.
    Procedure: Playwright headless chromium against stack running in CI.
    Coverage required: login/logout, main CRUD flow, form validation, error handling.
    Threshold: 0 failures; flakiness < 5%.

12. secrets-management.md
    Gate: runs BEFORE any other CI check.
    Tools: gitleaks detect --source . --exit-code 1
    Local hook: .git/hooks/pre-commit calls gitleaks protect --staged
    Rules: .env in .gitignore; .env.example values must be placeholders only.

13. performance-testing.md
    Gate: optional but required before first production deploy.
    Tool: k6 with 10 VUs, 30s duration.
    Thresholds: p95 < 200ms, error rate < 0.1%, throughput > baseline × 0.8.
    Baseline stored in .sdlc/memory/perf-baseline.json.

14. auto-merge-policy.md
    Confidence score: score starts at 1.0 and decreases per penalty.
    Auto-APPROVE threshold: score ≥ 0.95.
    Hard blocks (score = 0): auth/ changes, production DB changes, explicit ESCALATE.
    Auto-merge gate: Doctor=0 + all CI green + Reviewer APPROVE → merge automatically.

15. iac-generation.md
    Trigger: when Architect finalizes docs/architecture/overview.md.
    Procedure:
    - Generate app/infra/terraform/ modules from architecture spec
    - Modules: database/ (PostgreSQL), cache/ (Redis), backend/ (container), frontend/ (CDN)
    - Run: terraform init -backend=false && terraform validate && terraform fmt -check
    - No hardcoded values — all in variables.tf with sensitive = true for secrets.

TASK CREATION SKILL (task-creation.md)
====================================================================

The task-creation.md skill defines how every agent-created plan must be structured.
The Planner subagent must reference this skill as its primary skill.

Task Naming Convention:
  Every task name must follow this format:
  [AI][TYPE] Short imperative title (max 8 words)

  TYPE values: PLAN | BACKEND | FRONTEND | INFRA | QA | REVIEW | ARCH | FIX | DOCS

  Examples:
  - [AI][BACKEND] Add internal work-item API endpoint
  - [AI][INFRA] Setup SDLC observability tool
  - [AI][QA] Validate Plane MCP integration

Required plan sections (in order):

1. Story
   Narrative context explaining why this task matters.
   Written in plain English. 3-5 sentences minimum.
   Must connect to a business or product need.

2. Scope
   Bullet list of what is included.

3. Non-Goals
   Bullet list of what is explicitly excluded.

4. Assumptions
   Table with: Assumption | Confidence | Impact if wrong

5. Risks
   Table with: Risk | Likelihood | Impact | Mitigation

6. Impacted Areas
   Table with: Area | Files / Systems | Change Type

7. Acceptance Criteria
   Numbered list of measurable, testable criteria.
   Each criterion must be verifiable without ambiguity.

8. Definition of Done (DoD)
   Checkbox list. Must include:
   - [ ] Required ADRs written and accepted (if architectural decision made)
   - [ ] Unit tests pass locally
   - [ ] Integration tests pass (if applicable)
   - [ ] make sdlc-doctor exits 0
   - [ ] Relevant docs updated
   - [ ] No secrets in code or diff
   - [ ] PR reviewed and approved (human or Reviewer agent)
   - [ ] Handoff summary written in docs/handoff/current-state.md

9. Task Breakdown
   Subtasks using the same [AI][TYPE] naming convention.
   Each subtask: title | owner agent | estimated complexity

10. Next Step
    Single clear instruction for the next agent or human action.

Plan quality gates (self-check before delivery):
- All 10 sections present
- Task names follow [AI][TYPE] convention
- DoD has at least 6 checkboxes
- Assumptions table has confidence levels
- Next Step is a single, actionable sentence

Observer subagent responsibilities:

- Call post_task.py at task end to close the run with outcomes.
- Set hallucination_flag when agent claims success but evidence says otherwise.
- Set regression_flag when Doctor or tests fail after claimed success.
- Alert when quality thresholds are crossed (completion rate < 80%, hallucination rate > 5%).

IssueAnalyst subagent responsibilities:
- Triggered on every new GitHub Issue.
- Classify issue as bug/feature/infra/docs/security.
- Post a structured comment with analysis and suggested branch name.
- Create Plane card linked to the issue.
- Apply labels (priority, type, stage).

SDLCAuditor subagent responsibilities:
- Execute python3 app/infra/sdlc_obs/auditor.py autonomously.
- Interpret Autonomy Score and Health Score.
- Open GitHub Issues for every FAIL result.
- Update .sdlc/memory/operational-context.md with audit results.

MigrationRunner subagent responsibilities:
- Triggered after any change to app/backend/migrations/ or app/backend/models/.
- Provision isolated test PostgreSQL (Docker or DATABASE_URL_TEST env var).
- Run: alembic upgrade head — capture output and exit code.
- Run: alembic downgrade -1 — verify reversibility.
- Validate schema with SQLAlchemy inspect() against models.
- Post result as PR comment. Block merge if migration fails or is irreversible.

ContractValidator subagent responsibilities:
- Triggered after any change to app/backend/ endpoints or app/frontend/ API calls.
- Start FastAPI and export OpenAPI spec to openapi.json.
- Run openapi-typescript openapi.json → api.generated.ts.
- Diff against app/frontend/src/types/api.ts.
- Block merge if fields removed or types changed without explicit Implementer approval.

AutoFixer subagent responsibilities:
- Triggered on second consecutive CI failure on same PR.
- Parse CI output and match against known error catalogue.
- Create branch fix/SDLCINVEST-N-auto-fix-<category>.
- Open PR with: original error, patch applied, regression test added.
- Maximum 3 attempts — escalate to Implementer with diagnosis after 3rd failure.
- Never removes tests or silences linter to make CI pass.

RollbackAgent subagent responsibilities:
- Triggered when Observer detects regression_flag=1 after a merge, or health check fails 60s+.
- Identify merge commit causing degradation (by timestamp + git log).
- Read rollback plan from PR body (## Rollback section).
- Create branch hotfix/rollback-pr-N, apply git revert -m 1 <merge_commit>.
- If migrations exist: invoke MigrationRunner for downgrade.
- Open rollback PR and record incident in .sdlc/memory/incidents.md.
- Never executes rollback without documented plan in the original PR.

SecurityScanner subagent responsibilities:
- Triggered on every PR before Reviewer is notified.
- Run: bandit -r app/backend/ (Python SAST).
- Run: npm audit --audit-level=high (Node dependencies).
- Run: trivy image (if Dockerfile changed).
- Run: gitleaks detect (secrets in diff).
- Block merge on CRITICAL or HIGH findings.
- For CRITICAL: create private GitHub Issue in addition to PR comment.

SDLC OBSERVABILITY REQUIREMENTS
====================================================================

Create app/infra/sdlc_obs/ — the SDLC pipeline observability tool.
Uses only Python standard library and SQLite. Zero external dependencies.

Purpose: measure the AI-Native SDLC process itself.

Metrics to track per run:

| Metric            | Field               | How measured                              |
|-------------------|---------------------|-------------------------------------------|
| Precision         | completion_rate_pct | completed runs / total runs per stage     |
| Cost              | cost_usd            | OpenAI token cost reported by agent       |
| Time              | duration_ms         | wall-clock from start_run to end_run      |
| Tool success rate | tool_success_rate   | tool_calls_success / tool_calls_total     |
| Hallucination rate| hallucination_flag  | set when agent claims pass but evidence fails |
| Completion rate   | completion_status   | completed | failed | escalated | abandoned |
| Regressions       | regression_flag     | Doctor/tests failed after claimed success |

Required files:

1. app/infra/sdlc_obs/schema.sql
   SQLite schema with sdlc_runs table and sdlc_metrics view.

2. app/infra/sdlc_obs/collector.py
   Python API: Collector class with start_run(), end_run(), get_kpis(), get_runs(), get_summary().
   Uses sqlite3.Row so column names are always aliases, never raw SQL expressions.

3. app/infra/sdlc_obs/server.py
   Stdlib HTTP server. Endpoints:
   - GET /           → HTML dashboard (auto-refresh 30s)
   - GET /api/kpis   → JSON top-level KPIs
   - GET /api/summary → JSON per stage/agent aggregates
   - GET /api/runs   → JSON recent runs (query: ?limit=N&stage=S)
   Default port: 7700.

4. app/infra/sdlc_obs/hooks/pre_task.py
   CLI: opens a run, writes run_id to .sdlc_obs_state.json.

5. app/infra/sdlc_obs/hooks/post_task.py
   CLI: reads run_id from .sdlc_obs_state.json, closes run with outcome metrics.

6. app/infra/sdlc_obs/hooks/emit.py
   Shared state file management (write_state, read_state, clear_state).

Important implementation notes:
- Directory must be named sdlc_obs (underscore), not sdlc-obs (hyphen).
  Python cannot import modules with hyphens in directory names.
- All imports use: sys.path.insert(0, repo_root); from app.infra.sdlc_obs.collector import Collector
- Add app/infra/sdlc_obs/data/ and .sdlc_obs_state.json to .gitignore.
