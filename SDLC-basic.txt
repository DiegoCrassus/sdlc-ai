# SDLC-basic — bootstrap prompt

Use this prompt to recreate a new repository with the same minimal AI-Native SDLC operating system used here.

---

You are building a vendor-free AI-Native SDLC operating system for a software repository.

Create a minimal but strong SDLC structure where:

- `README.md` files are indexes. Every long-lived directory must have a short `README.md` explaining purpose, when to read it, owned files, boundaries, and related modules.
- `.sdlc/` owns machine-readable SDLC configuration, deterministic scripts, runtime memory policy, gates, gateways, and process authority.
- `.cursor/` owns Cursor-specific agents, rules, commands, skills, hooks, and MCP configuration.
- `docs/` is for product, architecture, infrastructure, operations, roadmap, and handoff documentation. Do not put SDLC process guides under `docs/`.
- `app/` is product code only.
- Plane is the workboard source of truth. Do not create local ticket folders such as `specs/`.
- Handoffs use Markdown tables, not YAML code fences.
- Product implementation is delegated to subagents. The chat Orchestrator coordinates and does not write product code directly.

## Core behavior to implement

1. Create `AGENTS.md` as the L0 entry point. It must say the chat agent is the Orchestrator, coordinates only, and delegates product implementation to subagents.
2. Create `.sdlc/sdlc.yaml` as the L2 machine index. It must list `contract.modules`, vendor settings, important paths, and governance references.
3. Create `.sdlc/process/master-workflow.md` and `.sdlc/process/change-lifecycle.md` as the L1 process authority.
4. Create `.sdlc/gates/paths.yaml` plus `.sdlc/dsl/gate.py` and `.cursor/hooks/sdlc_gate_hook.py` to block protected writes unless the session gate is open for the correct stage.
5. Create `.sdlc/gateways/policy.yaml` plus `.cursor/hooks/sdlc_pre_gateway.py` and `.cursor/hooks/sdlc_post_gateway.py` to evaluate each interaction before and after it runs.
6. Configure `.cursor/hooks.json` with session observability, write gates, pre-gateway, post-gateway, and post-tool silent-error validation.
7. Create `.sdlc/memory/orchestrator-handoff.md` using pure Markdown sections and tables. Required routing fields are `Next agent`, `Stage complete`, and `Previous agent`.
8. Create `.sdlc/doctor/checks.yaml` plus `.sdlc/dsl/doctor.py` so `make sdlc-doctor` validates required directories, required files, YAML validity, forbidden legacy paths, and README markers.
9. Create `.cursor/commands/sdlc-run.md` as the single normal command for starting or resuming the full SDLC loop.
10. Keep the SDLC minimal. Do not create `.sdlc/meta`, `.sdlc/settings`, `.sdlc/guides`, `.sdlc/references`, `docs/sdlc`, `docs/helper`, `docs/references`, or old flat root YAML files under `.sdlc/`.

## Handoff format

Use this exact style:

```markdown
# Orchestrator Handoff (latest)

## Routing

| Field | Value |
|-------|-------|
| **Next agent** | planner |
| **Stage complete** | yes |
| **Previous agent** | intent-analyst |

## Classification

| Field | Value |
|-------|-------|
| **Intent** | FEATURE |
| **Confidence** | 0.9 |
| **Requires Plane** | yes |
| **Requires branch** | yes |

## Session

| Field | Value |
|-------|-------|
| **Card** | INVES-N |
| **Epic** | INVES-M |
| **Branch** | feature/INVES-N-slug |
| **Stage** | implementation |

## Scope

Short prose describing the work unit.

## Acceptance criteria

- Criterion 1
- Criterion 2

## Blockers

- none

## Notes

Optional evidence, commits, PR URLs, decisions, and deferred items.
```
