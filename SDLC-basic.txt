WORKFLOW MODEL — ORCHESTRATOR + TASK DELEGATION (MANDATORY)
====================================================================

The chat agent is the Orchestrator Principal. It coordinates; it does NOT implement.

Golden rule:
  If the Orchestrator would Write app/, git commit, pytest, or ruff — STOP and Task(subagent).

Required rules (alwaysApply):
  .cursor/rules/001-sdlc-anti-bypass.mdc
  .cursor/rules/002-sdlc-orchestrator-principal.mdc
  .cursor/rules/003-orchestrator-delegation-only.mdc

Required skill:
  .cursor/skills/subagent-delegation/SKILL.md

Session loop (product work):

  Task(Intent Analyst)
  → Task(Planner): epic [AI][EPIC] + child cards + validate-all
  → workflow discover
  → Task(Architect) — notes on Plane epic
  → FOR EACH child card INVES-M:
       workflow start --card INVES-M   (NEVER on epic)
       Task(Implementer)  → autonomous commits on feature branch
       Task(QA)           → qa-minimum-checklist
       Task(AutoFixer)    → max 2 cycles if QA fail
       Task(Reviewer)     → APPROVE | ESCALATE
       Task(DevOps)       → push + PR (no human ask)
       workflow finish
  → epic Done when all children Done

Autonomy policy:
  "No interruptions" / "urgent" = full pipeline, zero human prompts for commit/merge
  Autonomy ≠ bypass — gates and delegation are never skipped

Human escalation only when:
  AutoFixer exhausted (2 cycles), Reviewer ESCALATE, or external API blocker

AI NATIVE SDLC MODEL (10 STAGES)
====================================================================

1. Ticket       — Capture intent, constraints, acceptance criteria
2. Requirements — Refine scope, assumptions, risks, non-goals
3. Architecture — Define approach, boundaries, trade-offs
4. Implementation — Scoped tasks via Task(Implementer)
5. Validation   — Task(QA) with real evidence
6. PR & Review  — Task(Reviewer) → APPROVE | ESCALATE
7. Deployment   — Task(DevOps) merge + rollback notes
8. Observability — Logs, metrics, SDLC obs hooks
9. Incident     — Diagnosis, mitigation, post-mortem
10. Auto Fix    — Task(AutoFixer) from CI/doctor evidence

Represented in .sdlc/lifecycle.yaml, stages.yaml, workflows.yaml.

TASK NAMING CONVENTION
====================================================================

Format: [AI][TYPE] Short imperative title (max 8 words)

TYPE values:
  EPIC      — parent tracking card (never workflow start)
  BACKEND   — app/backend/
  FRONTEND  — app/frontend/
  INFRA     — app/infra/, docker, CI
  SHARED    — app/shared/
  SDLC      — .sdlc/, .cursor/, governance
  DOCS      — docs/ only
  FULLSTACK — DEPRECATED as sole card for greenfield/FEATURE
              Split into BACKEND + FRONTEND child cards

Examples:
  [AI][EPIC] MarketPulse — delivery epic
  [AI][BACKEND] Add market data API with mock providers
  [AI][FRONTEND] Build dashboard with charts and watchlist
  [AI][INFRA] Add docker-compose for local stack

Required plan sections (every Plane card):
  Story, Scope, Non-Goals (≥2), Assumptions, Risks (≥2),
  Impacted Areas, AC (≥3), DoD, Task Breakdown, Architecture notes
